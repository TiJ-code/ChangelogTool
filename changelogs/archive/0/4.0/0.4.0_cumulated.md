## Config Parser
- added config schema version 3 (config.v3.dtd) with components and component-ref-based topics
- added config schema validation (config.v3.xsd) with maximum topic and component depth validation
- refactored configuration parser to support reusable components and topic views
- refactored integration of XSD validation into version 3 configuration parsing
- refactored backwards compatibility with configuration versions 1 and 2, mapping legacy topic entries onto a synthetic default component/topic pair
- refactored module exports to expose the config model package
### Breaking Changes: Major
- added reusable hierarchical component definitions
- added configurable changelog topics referencing components

## Markdown
- added rendering of nested component hierarchies as progressively deeper markdown headers
- added support for an unlabeled "default" topic whose components render without a top-level topic header
- refactored markdown builder to walk configured topics and their component trees rather than a flat topic list
- refactored changelog parser to validate topic and component references against the component-aware config, dropping the old per-topic category count limit

## Patches
- added patch.v2.dtd schema for the new component element
- refactored patch parser to the new component model
- refactored backwards compatibility with version 1 patch files, now resolving against configured components instead of topics
- refactored changelog builder to assemble output from configured topics and their referenced components, including nested component XML elements
- refactored reduced config to expose component identifiers in place of raw topic values
- refactored main entry point to load the full config so component-based processing has access to topic/component definitions
### Breaking Changes: Major
- added component-based patch format (v2) replacing topic-based patches

## Versioning
- removed unused POMParser utility class

## XML Model
- refactored XML model by replacing XmlTopic with XmlComponent, keyed by hierarchical path instead of name
- refactored XML constants to match the component-based patch schema
- added XmlPatch record representing a full parsed patch as a list of components
